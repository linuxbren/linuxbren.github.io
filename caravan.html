Caravan is the layer between your chat client and the model servers on a small group of Apple Silicon Macs. When a model won’t fit on one 24 GB mini, it splits the layers across both — over a Thunderbolt cable — and keeps each conversation’s memory warm so the next message doesn’t re-read the whole chat.

what it does

Point an OpenAI-compatible client at Caravan’s proxy. It routes each request to llama.cpp for GGUF models (the common packed weights you get from Ollama and friends) or to Caravan’s own MLX worker (Apple’s local-AI stack) based on the model name. Requests run one at a time. Each chat is recognized by a fingerprint of its first real message, so its cache is reused from turn to turn and saved to disk — it comes back after a restart.

When the model is split, the lead is the Mac you talk to: it serves the API, runs the last layers, and picks each token. The other Mac is a packer — it runs the first layers. The whole group is the string.

lead

The Mini you talk to. API, last layers, picks the next token.

packer

Runs the first layers and ships the hidden state over Thunderbolt.

string

The whole group. Today: two M4 minis, 24 GB each.

measured on the lab minis

All numbers below are measured on two Mac mini M4s with 24 GB each. “tok/s” means tokens per second — roughly how fast it writes a reply, or how fast it reads a prompt. Full tables live in the repo’s BENCHMARKS.md.

19 → 10 GB

Peak memory per Mini for Qwen3 30B on MLX: whole model on one Mac vs split across two. Gemma 4 17→9 GB, GPT-OSS 13→7 GB. A 16k-token Qwen3 chat that used to run out of memory now fits.

~1.6×

Two chats overlapped on the split: while one Mini works on chat A, the other works on chat B. Wall writing across chats rises about 1.6× (Qwen3 44→73, Gemma 37→61, GPT-OSS 34→54 tok/s). A single chat on its own isn’t faster.

status

Early and experimental. main is v2.1. The two-Mac MLX split is on caravan-v3-mlx-split, latest tag v3.4, waiting for review — not merged yet. It runs one personal assistant on a pair of M4 minis (24 GB each). It isn’t packaged, and it hasn’t been tested on other setups. The launchd plists still contain machine-specific paths.

The split itself is started by hand today; the agent and launchd still bring up a one-Mac MLX worker. Writing on the split is still slower than one Mac for a single chat (worth it when the model or the long chat doesn’t fit). Next up on the roadmap: guess-ahead decoding.
